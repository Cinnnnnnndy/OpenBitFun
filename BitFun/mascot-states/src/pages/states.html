毕方 · 多状态形象变体

以视频里的方块毕方为底座（等距圆角方块、白色短天线、侧面一对竖椭圆小眼），参考 Meta Muse 的吉祥物 Jolly 的做法，让形象从“装饰”变成“Agent 正在做什么”的可视化：14 个状态，覆盖感知思考、执行、需要你、结果与离线。3D 另有光滑 / 金属 / 毛绒三种质感，平面版只有纯色一种；颜色只用一套统一色板（18 种身体色 + 7 种天线球色，“自己搭配”“配色方案”同源），可在下方切换。

视频原版 · 光滑终端黑
身体 = 品牌识别矮胖的等距大圆角方块：顶面柔光、边缘一道细高光、侧面明暗过渡，天线球带玻璃高光。可爱来自比例，高级来自材质。所有状态形体一致，只允许压扁、果冻晃动这类弹性形变。
天线球 = 状态灯颜色区分大类（思考 / 执行 / 需要你 / 完成 / 异常 / 离线），动效区分细分状态。小到 18px 也认得出。
眼睛 = 注意力与情绪默认只有一对眼睛，长在右侧面并跟随等距透视，不画嘴、不画腮红。眼睛颜色按身体深浅自动选择（深色身体白眼、浅色身体黑眼）。7 种眼型：常态、放大、专注、眯眼、亮眼（完成）、眼缝（离线）、><。视线方向告诉你它在看哪里。
道具 = 具体任务键盘、清单、放大镜、终端、分身……只在 ≥64px 的大尺寸出现，小尺寸自动去掉。

名字的来历：《山海经》里的毕方

毕方是《山海经》里的一种神鸟，最主要的记载在《西山经·西次三经》：

又西二百八十里，曰章莪之山……有鸟焉，其状如鹤，一足，赤文青质而白喙，名曰毕方，其鸣自叫也，见则其邑有讹火。

意思是：章莪山上有一种鸟，样子像鹤，只有一只脚，青色的身子带着红色花纹，嘴是白的，名叫毕方，叫声就是“毕方”两个字；它出现的地方，城里就会发生怪火。

火的征兆毕方最出名的身份是“火鸟”。它不是火神，而是“见则有讹火”的兆头，后来民间常把它和火灾、防火联系在一起。
人面一脚《海外南经》写作“毕方鸟在其东……其为鸟人面一脚”，长着人脸、一只脚，与《西山经》的描述略有不同。
为黄帝驾车《韩非子·十过》讲黄帝在泰山会合鬼神，“驾象车而六蛟龙，毕方并辖”，毕方在车旁随行护卫。
木之精《淮南子·氾论训》有“木生毕方”，汉代高诱注为“木之精也”；木能生火，正好和它与火的关系对上。

和形象的对应：方块上那根天线，像毕方用一只脚站着；天线球随状态变色，也合“一出现就预示着什么”的意象。统一色板里的“毕方”特别版按原文取色——青色身体（青质）、侧面几道红色羽纹（赤文）、眼睛下方一只白色的喙（白喙）。

视图 × 质感 × 统一色板

同一个方块，两种视图：3D 等距视角用于主视觉、启动页、空状态；平面正视图只有一种：纯色、无质感、无阴影，用于图标、头像、状态胶囊、表情包这类小尺寸或扁平界面。三种质感只用在 3D 上，颜色来自统一色板：光滑还原视频里的软胶质感，适合产品内的图标与状态；金属是带清晰环境反射带的亮面金属外壳，适合发布会、硬件和高规格场景；毛绒参考华为鸿蒙“憨憨”的长毛绒质感，绒毛成簇、根暗尖亮，平时随身体轻轻起伏，鼠标划过时像被摸了一下（撸毛），更适合周边、贴纸、运营物料和 IP 传播。上排点选身体色，下排点选做法，整页一起切换。

从 Muse 借鉴什么

Muse 的吉祥物 Jolly 由设计师 Alex Cornell 设计，出发点是“怎么让用户看见后台 Agent 正在做什么”。我们借的是方法，不是长相。

01

形象在“干活”

Jolly 在 App 顶部开心地敲键盘，状态就是动作本身，而不是一个旋转的 loading。

毕方转译每个工作状态都配一个能看懂的动作：敲键盘、举清单、拿放大镜、盯终端。
02

形象 + 状态胶囊

Muse 最早设计的 UI 就是顶部的 status pill，实时写着“正在查比分”这类具体动作。

毕方转译形象负责情绪和类别，胶囊负责精确信息（文件名、进度、耗时）。两者永远成对出现。
03

极简五官承载情绪

Jolly 只有豆豆眼、上扬嘴角和腮红，靠极少的元素传递亲和感。

毕方转译比 Jolly 更克制：默认只用一对竖眼，情绪靠眼型和天线表达。另备一套“萌”表情（小嘴 + 腮红），留给贴纸、节日等轻松场景。
04

可延展的 IP

GitHub、Spotify 等品牌给 Jolly 做了联名变体，用户也能自定义外观。

毕方转译方块是稳定底座，质感、配色、天线球与道具都是可替换插槽；本文件的“自己搭配”就是让用户自行组合身体和天线球颜色。

色卡与搭配

形象的颜色从产品出发：底色与文字沿用 OpenBitFun 现有的暖白 / 暖灰体系，形象是界面里唯一大面积的彩色。天线球会随状态变色，所以每套身体配色都和 6 个状态色一起校过：同色系撞色时自动换成加深版，待命主色一律避开状态色相，保证“看颜色就知道状态”。

① 产品基底 取自 openbitfun-mobile 的 CSS 变量，形象周边的文字、卡片、描边都用这一组

② 状态色 天线球专用，全配色通用；饱和度与明度统一；默认搭配下，待命色与状态色的最小色相间隔为 28°

③ 身体配色 每套 = 身体三面 + 眼睛 + 天线杆 + 待命主色；按套使用，不拆开混搭

④ 搭配校验 每套配色 × 每个状态的实际天线颜色；加深 = 与身体同色系，已替换为加深版

身体弱化，彩色只给天线球天线球会随状态变色，所以身体用明亮、干净的浅马卡龙色：提亮度、不加灰，暗面用同色相的深一档而不是灰色，球依然是最饱和的那个颜色。界面保持暖白 / 暖灰，球和胶囊圆点是唯一的彩色来源。
状态色不进身体状态色只出现在天线球、胶囊圆点和少量道具上，从不给身体上色。
待命色避开状态色相待命主色只从青、莓果紫红、青柠等“空闲色相”里选，不能是紫 / 蓝 / 琥珀 / 绿 / 红，否则会被误读成某个状态。
同色系自动加深只在身体颜色较浓（如曜石黑之外的彩色身体、联名款）且与状态色相差 < 30° 时，才换成该状态的加深版；当前开心果、天空蓝、香芋紫、蜜桃各有 1–2 个状态使用加深版，见上方校验表。
完成 = 产品成功色“完成”的绿与产品 --status-success（#27C46A）同一色相，只是略提亮以配合马卡龙身体。
文字不用彩色状态胶囊里的文字始终用墨色 #171717，只靠右侧小圆点带颜色。

状态全集

按天线颜色分为 7 类，共 14 个状态。每张卡是一个小舞台：顶部一束光，状态色在天线球附近晕开，道具里的线条也取状态色，随上方的视图、质感、配色切换一起变化；舞台可切换浅色 / 深色。

舞台

小尺寸可读性

在会话列表头像（18px）、状态胶囊（22px）这类位置，3D 的透视和明暗会糊成一团，所以 32px 以下自动换成平面图标版：正视、眼睛和天线球放大、去掉阴影与特效，只靠“球的颜色 + 眼型”区分状态。

      使用规则

      一次只表达一件事同一时刻只显示一个状态。并行任务用“多 Agent 协作”统一表达，不叠加多个道具。
      情绪高点要克制“完成”跳 2–3 次后回到待命；“出错”只摇一次并停住；“等你确认”是唯一持续吸引注意的状态。
      状态切换 ≥ 600ms短于 600ms 的步骤合并显示，避免形象抽搐；切换时只换天线颜色与眼型，身体不跳。
      尺寸分级≥64px：完整道具；32–63px：去掉道具；<32px：自动切换为平面图标版——正视、眼睛和天线球放大、去掉阴影和天线特效，只靠球的颜色和眼型区分状态。
      颜色只属于天线状态色不染身体、不染眼睛。换配色时只换身体和待命主色，状态色（紫/蓝/琥珀/绿/红/灰）全套通用。
      尊重减少动效系统开启“减少动态效果”时全部静止，状态仍可通过天线颜色和眼型识别。

      全部 SVG 由 src/build.js 生成到 dist/assets/：svg/（完整版，含道具）、svg-compact/（去掉道具的中尺寸版）、svg-icon/（32px 以下的平面图标版），按“视图-质感-配色”分目录，每个文件自带动画。
